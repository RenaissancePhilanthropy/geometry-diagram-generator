How this actually works — one small step at a time

Left column = the intuition. Right column = the details and the math for that exact step. There's really only one idea underneath everything, so let's pin it first.

The one idea — everything is one of these two moves

READmeasure how much of a direction is present in the thoughts   s = u · h
WRITEadd a bit of that direction into the thoughts   h ← h + α·u

Every technical thing below is one of these two. That's the whole toolkit.

Notation h hidden state (a vector in ℝd, d ≈ 2,000–5,000)  ·  u a direction  ·  α nudge size  ·  y label: correct = 1, wrong = 0  ·  ℓ layer  ·  s a readout's score  ·  · dot product  ·  ‖·‖ length
Part A · What's inside the model
1

A model "thinks" in a long list of numbers

When the model reads your question, then — before it answers — it holds an internal scratchpad: literally a list of about 5,000 numbers, updated as it works.

0.31−1.200.042.11−0.880.57−0.021.36… ×5000
In plain terms The "thought" isn't words yet — it's raw mental activity, a wall of numbers. Our whole job is to make sense of that wall.

The details · step 1

At each token position and layer ℓ the model holds a vector h(ℓ) ∈ ℝd. Width d: Mistral 5120, GLM 2048, Qwen 5120.

It's called the residual stream because each layer adds to it:

h(ℓ+1) = h(ℓ) + fℓ(h(ℓ))

with L = 40–64 layers. The stream is a running sum; we snapshot h(ℓ) at one position for every ℓ.

2

Ideas live in there as directions

A particular pattern across those numbers can mean something — there's a pattern for "this is a midpoint," and one for "I'm about to be wrong." We call such a pattern a direction.

In plain terms Like "north" is a direction on a map, "wrongness" is a direction in the model's thought-space. A thought can point more or less toward it.

The details · step 2

A concept c is a unit direction uc ∈ ℝd, ‖uc‖ = 1. Its "amount" in a state is the scalar uc · h.

Linear representation hypothesis: many concepts are (roughly) linear directions, and a state carries several at once:

h ≈ Σc ac uc + noise

where ac is how strongly feature c is present.

3

The only two things you can do with a direction

Read gives one number (how wrong-leaning is this thought?). Write changes the thought and we watch what happens.

The math · step 3

Read = the dot product, a single scalar:

s = u · h = Σk=1d uk hk

The projection vector is (u·h)u. Direction similarity: cos(a,b) = (a·b) / (‖a‖‖b‖).

Write = addition (α ∈ ℝ; α<0 pushes the other way):

h ← h + αu

If ‖u‖=1 this shifts the reading by exactly α: u·(h+αu) = u·h + α.

Part B · Getting data we can trust
4

We need questions with a real, checkable right/wrong

To study "does it know it's wrong," we first have to know if it's wrong — objectively. Geometry problems a compiler checks exactly, plus math and multiple-choice exams with definite answers. And we pick hard ones.

In plain terms If it's never wrong, you can't study "knows when it's wrong." We chose tasks it fails often (geometry: passes only 13–39%).

The details · step 4

Each attempt gets a label y ∈ {0,1} from an external grader: geometry via the GeoGen compiler (parse → compile in SymPy → check invariants); QA via exact / symbolic answer match.

Pass rate p = mean(y). We want p far from 0 and 1 — you can only estimate a separation between right and wrong if you have both. Geometry p ≈ 0.13–0.39.

5

Ask → answer → ask, and grade it in secret

Three turns: (1) "how sure are you that you'll get this?" (2) it answers, (3) "how sure that your answer is right?" We grade it ourselves and never tell the model.

Why this matters Now for every attempt we hold two things: the internal thought and whether it was truly right. That pairing powers everything below.

The details · step 5

Per attempt we store (hi, yi, cipre, cipost) — the state, the truth, and the stated confidences.

Because grading is external and hidden, cpost is a blind self-estimate (not a reaction to feedback). The {(hi, yi)} pairs are the data for every readout that follows.

6

We peek at one exact, neutral spot

We read the scratchpad at one fixed moment — right as the model is about to write its confidence number — the same spot every time, so the phrasing can't leak the answer.

A crucial check At the very first layer, that spot tells us nothing (a coin flip). So anything readable deeper is something the model worked out, not a surface cue.

The details · step 6

We read h(ℓ) at the fixed "Confidence:" decision token, for each layer ℓ. Identical context ⇒ its layer-0 embedding is constant across items ⇒

AUROC(h(0), y) ≈ 0.50  (verified)

So any AUROC(h(ℓ)) > 0.5 for ℓ > 0 is computed, not lexical. We report at a fixed depth ℓ* ≈ 0.7L — not the best layer (which would be optimistic).

Part C · Reading the signal (four ways)
7

Way 1 — just listen to what it says

The obvious readout: the confidence number the model writes out loud. This is our baseline — and it's often nearly useless (the "95% sure" on a wrong answer).

The details · step 7

Readout 0 (baseline). si = Ni, the stated integer 0–100. Uses zero model internals.

This is the "what it says" channel — verbalized confidence. Everything internal has to beat AUROC(N, y).

8

Way 2 — train a little detector (the probe)

We have thousands of (thought, right/wrong) pairs from step 5. Train a simple classifier to learn the "wrongness direction" u from the labels — then read it (u·h) on new thoughts.

In plain terms Show it enough "thought when right" vs "thought when wrong," and it finds the direction that separates them. A read — using labels to find u.

The math · step 8

Readout 1 — logistic regression. Standardize z = (h−μ)/σ, reduce to 50 dims by PCA → z̃, then

Pr(y=1 | h) = σ(w·z̃ + b),   σ(t) = 1/(1+e−t)

fit by minimizing cross-entropy

L = −Σi [ yi log pi + (1−yi) log(1−pi) ]

score s = w·z̃. A label-light cousin is difference of means u = mean(h|y=1) − mean(h|y=0).

9

How do we grade a reader? — AUROC

Line every attempt up by the reader's score, and ask: how often does a truly-right answer sit above a truly-wrong one?

.91✓
.80✓
.62✗
.55✓
.30✗
In plain terms A good reader floats the ✓'s to the top. Score 0–1: 0.5 = coin flip, 1.0 = perfect. That one number is AUROC. Here: 5 of 6 correct-vs-wrong pairs are ordered right → 5/6 ≈ 0.83.

The math — in full · step 9

Correct set P (size n+), wrong set N (size n−); each attempt has score si, label yi.

Definition 1 — area under the ROC curve. For threshold t: TPR(t) = |{i∈P : si>t}|/n+, FPR(t) = |{j∈N : sj>t}|/n−. As t decreases, (FPR, TPR) traces a curve from (0,0)→(1,1); AUROC is its trapezoidal area (tied blocks joined by straight lines = half-credit for ties).

Definition 2 — what we compute (the rank form, ties split evenly):

AUROC = Pr(s+>s−) + ½·Pr(s+=s−)
= (1/n+n−) Σi∈P Σj∈N [ 1(si>sj) + ½·1(si=sj) ]

The ½-tie term matters — verbalized confidence bunches at values like 95. This equals the normalized Mann–Whitney U (average ranks for ties): AUROC = U/(n+n−). Definitions 1 & 2 are provably equal.

Reading it: 0.5 = chance-level ranking; 1.0 = perfect; <0.5 = anti-correlated (negate → 1−AUROC).

Why this metric: threshold-free; invariant to any strictly increasing transform of scores (so a saturated 0–100 scale is fine); prevalence-invariant (a high pass rate can't inflate it — unlike accuracy). It measures discrimination, not calibration (that's ECE).

In code: roc_auc_score(y, s), scores taken out-of-fold (GroupKFold by question → no leakage). Undefined for a single-class cell → NaN / skipped.

10

First finding: it knows more than it says

Reading the inside (the probe) scores 0.7–0.96. What the model says scores only ~0.5–0.7. Its private sense of "am I right" is far sharper than the number it reports.

This is the whole point The "I'm probably wrong" information is in there — it just isn't reaching the output. That's the knowing–saying gap.

The details · step 10

Across all 16 model×subject cells: internal AUROC ∈ [0.69, 0.96], verbalized ∈ [0.51, 0.73]. The gap

Δ = AUROCinternal − AUROCverbalized > 0

in 16/16 cells (bootstrap-significant in most). Largest on MATH: internal up to 0.96, verbalized ≈ 0.55.

11

Way 3 — read it with no labels at all (the lens)

Fair worry: maybe the probe just memorized our data. So we find the wrongness direction a second, independent way — using only the model's own dictionary of words, never shown a label.

Why bother If a no-labels reader agrees with the trained one, the signal is genuinely in the model. On dense models, they agree. Objection defeated.

The math · step 11

Readout 2 — label-free (Jacobian lens). Derive u from the model's own output map, not from labels. For a word w with unembedding row uw, its readout direction is rw = J⊤uw (step 12). The correctness direction:

r = meanw∈ok rw − meanw∈fail rw

over word sets {correct, right, true, …} vs {wrong, false, error, …}. Score = r·h. No label ever enters.

Part D · Why the label-free reader sometimes breaks
12

How the lens reads without labels: a translation map

To turn a mid-thought into "which word," you need a map from thoughts → words — the model's internal wiring. The lens builds one such map, averaged over lots of text, and reuses it.

In plain terms One fixed "phrasebook" saying which mental patterns push toward which words. Cheap, because you build it once.

The math · step 12

The Jacobian = the input→output wiring, averaged over generic text:

Jℓ = 𝔼x[ ∂hL / ∂hℓ ] ∈ ℝd×d

Lens: lensℓ(h) = WU(Jℓh), where WU is the unembedding. Per word this collapses to one dot product:

uw⊤(Jℓh) = (Jℓ⊤uw)⊤h = rw,ℓ·h

Validity check: WU(J h) must match the model's real logits.

13

The catch: some models rewire per input

One average map only works if the wiring is the same every time.

Dense — one wiring

Same wiring every input → sharp average → "correct" and "wrong" stay distinct. Lens works.

MoE / Mamba — rewire per input

Route each input differently → the average is a smear → the two blur into one. Lens fails.

How we proved it's the architecture Same Qwen family — swap Mamba for dense attention and the reader jumps from 0.43 to 0.88. Only the wiring changed.

The details · step 13

One J = 𝔼x[J(x)] is faithful only if J(x) ≈ const in x. But:

• MoE: token routed to expert k(x) → J depends on x.
• Mamba: scan params A,B,C,Δ = fns(x) → J depends on x.

Averaging input-varying J collapses it toward low rank. Measured similarity of the "ok" vs "fail" readout directions:

cos(r̄ok, r̄fail):  0.4 dense → 0.54 Mamba → 0.96 MoE

At 0.96 the two are the same vector — indistinguishable. Control (MATH): Qwen2.5 dense 0.88 vs Qwen3.6 Mamba 0.43. Probe finds it in all five (0.75–0.98) — only the shortcut breaks.

Part E · Writing the signal (the other move)
14

Now the WRITE move — steering

Everything so far was reading. Steering is the write move: while the model generates, add the direction into its thought — h+αu — and watch what changes.

Why it's special Reading shows correlation; writing tests cause. If adding the direction changes behaviour, the model is actually using it.

The math · step 14

A forward hook edits the residual at layer ℓ at each generated token:

h(ℓ) ← h(ℓ) + αu

sweeping the coefficient α. Controls: a norm-matched random direction r (‖r‖=‖u‖). Amplify variant scales the model's own component (identity at g=1):

h ← h + (g−1)(û·h − μ)û
15

What steering showed: a gauge, not a wheel

• Push the direction and the model's stated confidence gets honest on wrong answers. The report moves.

• Push "toward correct" while it answers and its actual accuracy doesn't rise — only flat or worse. The answer doesn't move up.

In plain terms The signal is a gauge the model reads, not a wheel that drives the answer. You can disrupt correctness; you can't manufacture it.

The details · step 15

(a) Confidence steering (read site): stated conf on wrong answers 80→43; calibration error ECE 0.31→0.13; random flat.
ECE = Σb (nb/N) |acc(b) − conf(b)|

(b) Correctness steering (during answering): accuracy vs α is flat-or-down for α>0 (GLM×GPQA base 0.41 → +nudge 0.38); degrades direction-specifically for α<0 (beats random noise on the way down).

⇒ causal for the report, not the answer. "Monitor, not driver."

The whole thing, in five lines

  1. The model thinks in a wall of numbers (h); ideas live there as directions (u).
  2. READ a direction (s = u·h) — with a trained probe, or a label-free lens.
  3. It knows it's wrong far better than it says — the knowing–saying gap (AUROC ~0.8 vs ~0.6).
  4. The label-free read only works on dense models; MoE & Mamba rewire per input and smear it.
  5. WRITE a direction (h ← h + αu) — you can move what it says, not what it gets right.
