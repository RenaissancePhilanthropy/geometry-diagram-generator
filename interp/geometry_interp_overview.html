THE QUESTION01 — 13
The question

When the model draws a figure, does it
understand the geometry — and where?

  • An LLM is matrix math over token vectors. When it writes “M = midpoint of A, B”…
  • …is it shuffling symbols, or has it built an internal representation of the space?
  • If it has one: where in its layers does it form, and is it in a usable form?
  • This is mechanistic interpretability — opening the model up, not just judging its output.
WHY THIS SETUP02 — 13
Why our setup is special

Our pipeline gives ground truth for free.

  • Most LLM interpretability has no answer key — what is the “correct” internal state for an essay?
  • Our generator compiles every construction to exact geometry (SymPy): coordinates, angles, relations.
  • So for every token the model writes, we know the true geometric fact it should encode.
  • That answer key is what makes “decode the geometry from the activations” even possible.
THE METHOD03 — 13
The method

Capture the internal state, decode it, then test it causally.

STEP 01

Capture

Run the model; photograph its internal vectors at every layer, for each token.

STEP 02

Probe

Train a simple linear readout: can we recover a geometric fact from those vectors?

STEP 03

Patch

Swap an internal vector between near-identical prompts. Does the output change?

Probe = “is the information there?”  ·  Patch = “does the model actually use it?”

KEY INTUITION04 — 13
Key intuition — the residual stream

A token’s vector is a workspace that each layer rewrites.

  • A token starts as just its word; it flows up through ~28 layers, each adding an edit.
  • Attention is where tokens exchange info — “M” pulls in “A” and “B” to compute their midpoint.
  • A fact that combines tokens can’t exist at layer 0 — it must be built with depth.
  • We keep the probe linear, so “decodable” = “in a form the model’s own machinery can read.”

Remember this: layers are the time-axis of the model’s thinking. Late-layer facts were computed, not copied.

WHAT WE RAN05 — 13
What we ran

Two model sizes, rented GPUs, real exam geometry.

  • Models: Qwen2.5-7B (full precision) and Qwen2.5-32B (4-bit, to fit the GPU).
  • Prompts: GenExam geometry problems; the model writes constructions, we keep the valid ones.
  • Captured activations at all layers; trained probes for coordinates, angles, relations.
  • Ops: detached GPU runs, monitored every 20 min, crash-proofed for long unattended captures.

RESULT 02 · HEADLINE07 — 13
Solid

The model represents what each point is — beyond its name.

  • At the token naming a point, we linearly decode its geometric role: midpoint / perpendicular / intersection / foot…
  • Accuracy 0.70 (7B) → 0.86 (32B), and +0.37 above a “guess from the name alone” baseline.
  • Holds under leak-free evaluation, in both model sizes — our most robust claim.
  • The “lift over naming” is the control: midpoints are often called M; the signal beyond that is the real representation.
RESULT 03 · CAUSAL08 — 13
Solid

It doesn’t just store a value — it uses it.

  • Minimal pairs: “angle = 60°” vs “angle = 70°”, identical otherwise.
  • We overwrite the model’s internal vector at the angle, mid-computation.
  • The output flips 60 → 70 — so that representation causally drives behavior.
  • Decoding shows info is present; patching shows it is used. This is the stronger test.

THE BOTTLENECK10 — 13
Open

The real limit isn’t the method — it’s prompt diversity.

  • Every dataset had only 35–50 unique prompts.
  • We generated many samples per prompt — but that inflates counts, not variety.
  • Coarse facts (a point’s role) generalize from few prompts; precise coordinates do not.
  • To settle the coordinate-map question we need many more unique prompts, not more samples.
WHERE THIS GOES NEXT11 — 13
Where this goes next

Concrete next steps, in priority order.

  • 1. Capture with many more unique prompts (widen geometry tiers / generate variants).
  • 2. Re-run the full probe suite leak-free + multi-seed for error bars.
  • 3. Extend causal patching from “stated value” to the relational representation.
  • 4. Stretch: sparse-autoencoder features for interpretable geometric concepts.
  • All code, tests, and methodology are committed and reproducible.
